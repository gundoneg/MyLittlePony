# Перенос знаний между моделями разных архитектур без инференса донора

> Отчёт по результатам глубокого исследования (5 параллельных веб-агентов: рост/инициализация
> весов; dense→MoE upcycling; смена токенизатора/семейства; слияние и выравнивание в
> пространстве весов; теория/таксономия и ограничения). Дата составления: 30.05.2026.
>
> **Главный вывод:** знание можно переносить как (a) логиты/выходы, (b) фичи/активации или
> (c) веса/параметры. Категории (a) и (b) по определению требуют forward-pass донора. Полностью
> **без инференса возможна только параметрическая передача (c)** — но она надёжно лишь
> *ускоряет* обучение (инициализация), а не переносит способности «сама по себе».

## 1. Постановка
- Классический Knowledge Distillation (Hinton 2015, FitNets 2015) обучает ученика на «мягких»
  выходах/фичах учителя → **обязателен forward-pass учителя** на каждом примере.
- Наше ограничение жёстче: **донор не запускается вообще**. Это сразу отсекает почти весь KD.
- ⚠️ «Data-free» ≠ «inference-free». ZSKD, DeepInversion, DAFL не используют исходные данные,
  но **активно гоняют учителя** по синтетике — ограничение нарушают.

## 2. Таксономия: что переносим и нужен ли инференс донора
| Что переносим | Примеры | Инференс донора? | Между разными арх.? |
|---|---|---|---|
| Логиты/выходы | KD (Hinton), seq-level KD | **Да** | да, но дорого |
| Фичи/активации | FitNets, RegMean, ZipIt, OTFusion, stitching | **Да** | частично |
| **Веса/параметры** | рост, upcycling, learngene, merging, гиперсети | **Нет** | **только это и подходит** |

## 3. Семейство «знание = веса» (без инференса донора)

### 3.1 Рост / инициализация в той же семье (ширина/глубина)
- **Net2Net** (Chen 2015, arXiv:1511.05641) — функцию-сохраняющие Net2Wider/Net2Deeper.
- **bert2BERT** (arXiv:2110.07143) — FPI (точно сохраняет функцию) + AKI.
- **LiGO** (arXiv:2303.00980) — обучаемый линейный оператор роста (~50% экономии).
- **LEMON** (arXiv:2310.07999) — lossless-расширение ширины и глубины.
- **MSG** (arXiv:2305.02869) — рост по всем измерениям (вкл. головы) через маскирование.
- **Progressive Stacking** (ICML 2019) / **G_stack «Stacking Your Transformers»**
  (arXiv:2405.15319, ~54% ускорение) — стекаем обученные слои вглубь.
- Большое→малое: **Weight Subcloning** (Apple, arXiv:2312.09299), **Weight Selection**
  (arXiv:2311.18823) — отбор подмножества весов по важности.
- **Learngene / WAVE** (arXiv:2404.16897, 2406.17503) — конденсируем «ген» и разворачиваем в
  потомков переменного размера.
- Точно функцию-сохраняющие: Net2Net, bert2BERT(FPI), LEMON, MSG (нулевой стартовый рост loss).

### 3.2 Dense → MoE (upcycling) — наиболее релевантно репо
- **Sparse Upcycling** (Google, arXiv:2212.05055) — копируем dense-FFN в N экспертов + случайный
  роутер, дообучаем (~50% исходного компьюта).
- **Drop-Upcycling** (ICLR 2025, arXiv:2502.19261) — частичный реинит доли нейронов эксперта
  (по статистике весов донора) → ломает симметрию, выигрывает на сотнях млрд токенов.
- **BTX / Branch-Train-MiX** (Meta, arXiv:2403.07816) — параллельно учим доменных экспертов,
  затем собираем их FFN в MoE + роутер. Обобщает BTM и Sparse Upcycling.
- **NVIDIA «Upcycling LLMs into MoE»** (arXiv:2410.07524) — для **fine-grained** (много
  экспертов): virtual-group init, softmax-then-topK, weight scaling. Прямой инструмент для
  формы DeepSeek/Kimi.
- **Llama 3 → MoE** (arXiv:2412.09952) — 8 экспертов из сильного донора за **<1%** компьюта.
- Как делали на практике: **Qwen-MoE** (из Qwen-1.8B, 64 fine-grained эксперта, ~25% ресурсов),
  **MiniCPM-MoE**, **Skywork-MoE** — все upcycling. **DeepSeek-V3 (256) и Kimi K2 (384) —
  обучены С НУЛЯ, не upcycling.** Skywork предупреждает: ранний выигрыш upcycling на длинном
  горизонте может исчезнуть.

### 3.3 Смена токенизатора (тело копируется, меняются только эмбеддинги/LM-head)
- **WECHSEL** (arXiv:2112.06598), **CLP-Transfer** (arXiv:2301.09626), **FOCUS**
  (arXiv:2305.14481), **Trans-Tokenization** (arXiv:2408.04303) — инициализируют новые
  эмбеддинги как взвешенную смесь старых через статические/переводные эмбеддинги. **Без
  инференса донора.**
- **ZeTT** (arXiv:2405.07883) — гиперсеть, предсказывающая эмбеддинги под любой токенизатор;
  на этапе переноса инференса донора нет (если переиспользовать готовую гиперсеть).

### 3.4 Смена семейства архитектуры (самое сложное)
- **Transformer→Mamba**: в «Mamba in the Llama» (arXiv:2408.15237) **инициализация** SSM прямо
  из проекций внимания (Q/K/V/O → C/B/X) — без инференса; но опубликованный рецепт добавляет
  дистилляцию (**нарушает ограничение**). **MOHAWK/Phi-Mamba** (arXiv:2408.10189), **Llamba**
  (arXiv:2502.14458) — все стадии требуют forward-pass учителя.
- **XATL** (arXiv:2404.02684) — прямое копирование общих модулей (нормы, MLP, эмбеддинги) в
  другую архитектуру (напр. linear-attention). Без инференса.
- **Cross-LoRA** (arXiv:2508.05232) — **data-free И training-free** перенос LoRA-адаптеров между
  *разными* базовыми LLM через SVD-выравнивание подпространств. Выигрыш умеренный (~до 5%).

### 3.5 Слияние / выравнивание в пространстве весов
- **Без инференса:** Git Re-Basin **weight matching** (arXiv:2209.04836), **model soups**
  (uniform, arXiv:2203.05482), **task arithmetic / TIES / DARE** (arXiv:2212.04089, 2306.01708,
  2311.03099) — но требуют **ту же архитектуру** и общую предобученную базу. MergeKit
  passthrough / **FrankenMoE** — структурная сборка без инференса.
- **Требуют forward-pass:** Git Re-Basin activation matching, **OTFusion** (arXiv:1910.05653),
  **ZipIt!** (arXiv:2305.03053), **Fisher merging** (arXiv:2111.09832), **RegMean**
  (arXiv:2212.09849; «dataless» = без меток, но forward нужен), **model stitching**
  (arXiv:1411.5908, 2106.07682 — единственный изначально для *разных* сетей, но обучает стык).

### 3.6 Гиперсети / генерация весов
- **HyperNetworks** (Ha 2017, arXiv:1609.09106), diffusion-генерация весов (arXiv:2402.18153) —
  параметрический примитив; кросс-архитектурность пока ранняя стадия.

## 4. Честный итог и ограничения
- **Neural Incompatibility** (ACL 2025, arXiv:2505.14436): и PostPKT, и PrePKT (их LaTen) —
  кросс-масштабный параметрический перенос **не достигает стабильного результата**. **Beyond
  Neural Incompatibility** (arXiv:2510.24208) — улучшает через латентное выравнивание, но не
  решает.
- Надёжно и без инференса работает только **инициализация** (рост, upcycling, XATL, learngene):
  она *ускоряет предобучение*, но не переносит способности сама по себе.
- Единого обзора именно по «inference-free cross-architecture transfer» нет — тема разбросана.

## 5. Практический рецепт для репо (донор → новая модель, без инференса донора)
1. **Сопоставить модули** донора и цели (что общего: эмбеддинги, нормы, MLP, внимание).
2. **Выровнять размерности**: рост ширины/глубины — Net2Net/LEMON/G_stack; сжатие —
   weight subcloning/selection; разная ширина — SVD/проекция.
3. **Dense→MoE** (форма Kimi/DeepSeek): копия FFN в эксперты + **Drop-Upcycling** (частичный
   реинит) + **NVIDIA** (virtual-group init, softmax-then-topK, weight scaling).
4. **Смена токенизатора**: переинициализация эмбеддингов (FOCUS/WECHSEL), тело копируется.
5. **Смена семейства**: XATL (общие модули) + lossy init внимание→SSM; ожидать просадку.
6. **Continued pretraining на свежих реальных данных** (НЕ на выходах учителя) — «залечить»
   веса. Бюджет: от <1% (сильный донор, малое расширение) до ~50% (near-scratch).
7. **Контроль:** сравнить с обучением с нуля при равном бюджете (предупреждение Skywork).
